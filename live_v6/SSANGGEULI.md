# 쌍끌이 운영 및 전진 검증

## H 분할 익절

`bundle_v5`에서 `LIVE_V6_BUNDLE_H_EXIT_POLICY=h_exit_v2`를 선택하면 새 H 돌파 롱에 두 개의 거래소 익절 주문을 사용한다. 설정을 생략하면 기존 정책을 사용한다. 정책은 진입 요청을 기록할 때 고정되며 봇이 재시작하거나 설정을 해제해도 그 요청에서 생긴 포지션은 같은 조건을 따른다.

- 최초 손절은 기존 2 × 일봉 ATR(14)이다. 실제 진입가와 최초 손절가의 차이가 가격 기준 1R이다. 수량을 거래 단위로 내림해 +1R에 25%, +5R에 나머지를 건다. 분할 최소 수량을 만족하지 못하면 +1R 주문 하나로 전량을 닫는다.
- TP1 체결 후 잔량에는 수수료와 0.15% 여유를 반영한 본전 보호와 기존 추적 손절 중 높은 가격을 적용한다. TP2 이전에 손절이나 시간 청산으로 종료될 수 있다. 익절 주문이 부분 체결 후 만료되면 거래소 자식 주문의 체결량과 포지션을 확인해 미체결분만 다시 등록한다.
- `/status`의 수량·보호 주문과 마지막 거래소 확인 시각을 함께 본다. 진입 당시 계획 손실률은 계획 수량 × 손절 거리 ÷ 당시 지갑으로 계산된다. 실제 손익에는 체결 차이, 수수료, 펀딩이 더해진다.
- 시장가 분봉 재생에서는 기존 마크가격 손절을 우선하고 같은 봉에서 두 익절 가격을 통과하면 두 주문을 순서대로 처리한다. 새 본전 손절은 다음 분부터 평가한다. 모의 지정가 옵션은 시장가 장부의 청산에 지정가와 메이커 수수료를 대입한 추정치다. 체결 시각에 맞춰 고친 목표가나 호가 대기열을 검증할 때는 별도 자료가 필요하다.

검증 결과와 계좌 위험 예산별 차이는 [H 청산 정책 검토 기록](../docs/meeting-minutes/2026-11-25-h-exit-v2.md)에 있다.

### 운영 프로필

운영 유닛 `live_v6-live`는 릴리스에 포함된 [쌍끌이 운영 설정](deploy/ssanggeuli-live.env)에서 신규 H의 익절 방식과 위험 예산을 읽는다. H 예산은 지갑의 6%, M은 2%, D와 R은 0%다. 기존 포지션의 실제 수량과 주문 계획은 진입 당시 장부를 따른다. H 예산을 낮추면 기존 포지션이 차지하는 위험 금액 때문에 신규 진입이 잠시 제한될 수 있다.

호스트의 `95-ssanggeuli-profile.conf`는 `EnvironmentFile=-/opt/tradebot/app/current/live_v6/deploy/ssanggeuli-live.env`를 마지막으로 읽는다. 코드와 설정은 CI가 같은 릴리스로 전환한다. 이 파일이 없는 이전 릴리스에서는 호스트의 기존 설정을 사용한다. 배포 검증 시 실행 중인 PID의 `LIVE_V6_BUNDLE_H_EXIT_POLICY`, `LIVE_V6_BUNDLE_RISK_PCT`, `LIVE_V6_BUNDLE_MARGIN`과 거래소 보호 주문을 확인한다.

신규 적용을 해제하려면 v2를 이해하는 코드에서 프로필 선택을 해제한다. v2 진입이 대기 중이거나 v2 포지션이 열려 있을 때 `5722488` 코드로 되돌리면 해당 코드가 TP2를 취소할 수 있다. 이때는 대기 진입과 열린 포지션이 가진 정책을 계속 처리할 수 있는 릴리스를 사용한다.

## 거래가 없던 날 점검

번들 엔진은 평가 시각과 전략, 데이터 누락, 신호, 위험 검사 및 주문 진행을 일자별로 집계할 수 있도록 기존 이벤트 로그 디렉터리의 `<network>_decisions.jsonl`에 기록한다. 이 파일은 이 버전을 실행한 이후부터 쌓인다. 예전 로그가 없는 기간의 거래 여부는 거래소 이력과 기존 거래 장부를 따로 대조한다.

```sh
python -m live_v6.tools.bundle_decisions /path/to/mainnet_decisions.jsonl --day 2026-11-24
```

- `unobserved_elapsed_minutes`는 기록이 없는 시간이다. 예정 평가가 없었던 시간은 별도로 센다.
- `checks`와 `observed_reasons`로 달력 누락, 데이터 오류, 조건 미충족, 증거금·최소주문 거절을 구분한다.
- `no_terminal_observation`에는 제출·체결·거절 중 결과가 확정되지 않은 후보가 남는다. 실제 거래소의 현재 상태는 주문 ID와 포지션 조회로 확인한다.
- 텔레그램의 기존 `/status`에서 포지션 잔량, 마지막 거래소 대조 시각, 익절 수량·가격 및 잔여 주문 정리 상태를 확인한다. 주문을 취소했다는 응답 뒤에도 거래소 목록에 남아 있을 수 있다.
- 거래소가 시장가 주문을 받았는지 판단할 증거가 부족하면 동일 주문 ID와 선행 손절을 보존한다. 위험 노출을 확정할 수 없는 동안 엔진의 신규 진입이 보류될 수 있다. 임의로 주문을 다시 보내기 전에 거래소의 주문·체결 이력, 현재 수량 및 진입가를 대조한다.

## 두 방향 모의 연구

`paired-breakout-v1`은 BTCUSDT·ETHUSDT의 현물·무기한선물 공개 호가, 미결제약정, 펀딩을 사용한다. 최신 연속 20분 표본으로 돌파 기준을 계산한다. 현물도 오른 뒤 눌림을 버틴 경우 롱, 선물 주도 급등과 미결제약정 증가·양의 펀딩 뒤 돌파선 아래로 밀리고 재돌파에 실패하면 숏을 검토한다. 재시험·확인·진입은 서로 다른 수신 시점에서 결정한다. 강도는 설정이 처음 관찰될 때 고정한다.

```sh
python -m live_v6.tools.breakout_shadow collect --db breakout.sqlite3 --symbols BTCUSDT ETHUSDT
python -m live_v6.tools.breakout_shadow report --db breakout.sqlite3 --brief
python -m live_v6.tools.breakout_shadow report --db breakout.sqlite3 --details
```

첫 명령은 실행하는 동안 분마다 공개 데이터를 수집한다. 관측 원본을 내보낸 뒤 독립 장부에서 비교 결과를 재현할 수 있다.

```sh
python -m live_v6.tools.breakout_shadow export --db breakout.sqlite3 > observations.jsonl
python -m live_v6.tools.breakout_shadow replay --input observations.jsonl --db replay.sqlite3
```

**이번 버전의 사전 결정.** 같은 모의 진입을 최초 손절 위험 1 USDT로 맞춘다. 공통 익절은 +1R에 50%, 전략별 후보는 롱 +2R에 25%, 숏 +0.75R에 65%다. 위험 단위 R은 진입·손절 가격 차이를 기준으로 정의한다. 모의 수량은 손절 시 추정 거래 비용까지 포함해 계산한다. 매수·매도 호가, 표시 잔량, 편도 수수료 5bp·불리한 체결 2bp, 관측된 정산 펀딩을 적용한다. 분중 가격 경로와 실제 최소 주문 단위가 결과를 바꿀 수 있다.

**비교할 값.** 같은 진입에서 두 청산 방식이 모두 종료된 쌍의 순손익 차이를 본다. 강·보통 비교는 방향별·청산 방식별로 한다. 같은 15분에 여러 종목이 발생하면 구간 평균으로 묶는다. `closed_drawdown_R`는 그룹 내 종료 거래를 시간순으로 누적한 고점 대비 하락폭이다. 실계좌의 증거금·미실현손익·복리는 별도 검증이 필요하다. `reached_1R_then_loss`는 관측 호가가 한때 +1R에 도달한 뒤 순손실로 종료된 횟수다. 데이터 공백, 미확인 펀딩 및 부족한 호가 잔량으로 끝까지 평가할 수 없는 경우를 따로 센다.

**후속 판단.** 각 방향에서 강·보통별로 종료된 15분 구간이 각각 30개 모이면 첫 기술 통계를 검토한다. 그 뒤 새 기간에서 같은 결과가 나오는지, 비용과 미체결을 더 불리하게 잡아도 남는지, 결과를 좌우하는 한두 사건이 있는지 독립 검토한다. 같은 사건이 15분 경계를 넘을 수도 있다. 이 표본 수는 레버리지 상향 기준이 아니다. 모의 실험의 수집기와 보고서는 실주문 또는 레버리지 설정에 접근하지 않는다.

## 공식 일정 갱신 및 연구 분담

```sh
python -m live_v6.tools.calendar_watch --db calendar.sqlite3
python -m live_v6.tools.calendar_watch --month 2026-12 --db calendar.sqlite3 --candidate reviewed.csv
```

기본 범위는 미국 동부 기준 이번 달과 다음 달이다. BLS와 연준의 월별 원문, 해시, 수신 시각, 등록 일정과의 차이를 SQLite에 저장한다. 종료 코드 0은 일치, 1은 변경, 2는 자료 확인 실패다. 모든 출처를 확인한 경우에만 후보 CSV를 생성한다. 배포 중인 엔진은 시작할 때 지정한 CSV를 읽으므로 새 후보를 운영에 쓰려면 별도 검토와 반영이 필요하다. 연준이 정책 결정 발표를 제외한 2027년 10월 26~27일 전략회의는 분리했다. [연준 공지](https://www.federalreserve.gov/newsevents/pressreleases/monetary20261112a.htm)

연구자는 원문과 처음 알 수 있었던 시각, 새 가설이 돈을 버는 이유, 관측 전에 정한 실패 조건을 적는다. 다른 검토자는 당시 체결 가능성, 비용, 같은 사건의 중복, 시도한 후보 수를 확인한다. 리드는 같은 가설의 임계값 변형을 한 계열로 묶어 결정과 재검토 조건을 남긴다.

| 가설 | 이번 결정 | 재검토할 증거 |
|---|---|---|
| 52주 신저가 이탈 숏 | 기존 연구에서 보류. 개발 체결 19건이 사전 기준 30건에 미달했다. | 상장 이력과 유동성이 충분한 별도 모집단에서 새 데이터 확보 |
| 현물 동반 돌파 롱 / 선물 돌파 실패 숏 | 공개 데이터 모의 관측 | 강도별 새 사건, 동일 위험·동일 진입 청산 비교 및 누락 점검 |
| 강할수록 실전 비중 확대 | 실전 배수 유지 | 표본 밖에서 강도가 비용 차감 순손익을 구분하고, 여러 종목을 같은 자금으로 돌려도 버틸 수 있는지 검증 |
