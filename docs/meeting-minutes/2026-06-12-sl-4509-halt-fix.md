# 회의록 — SL −4509(포지션 없음) 오판 HALT 수정 (2026-06-12)

- **일자**: 2026-06-12
- **안건**: 0.4% 스캘프 전환 후 실거래 불필요한 emergency close + HALT 제거
- **절차**: 실거래 장애 분석 → 코드 수정 → pytest 검증 → 본 회의록 기록

## 배경

2026-06-09 0.4% 대칭 스캘프 전환 이후 실거래에서 SHORT 포지션이 정상 익절(+$2.28)에도 불구하고 봇이 emergency close + `set_manual_halt` 를 실행해 거래를 강제 중단하는 사태 발생.

실제 청산 흐름:
1. SHORT 포지션 진입 후 추매(물타기) 체결.
2. reconcile 루틴이 추매 체결을 감지하고 SL·TP 재배치 시작.
3. **그 찰나** 0.4% TP 가격에 도달 → TP(quantity 주문)가 먼저 체결 → 포지션 전량 청산됨.
4. SL 재배치(`_place_sl_order`)가 `closePosition=True` GTE TIF 주문을 Binance에 전송.
5. Binance는 열린 포지션이 없으므로 **−4509(AlgoNoOpenPosition)** 반환.
6. 기존 코드가 −4509를 "무방비(unguarded)" 로 오판 → `set_manual_halt` + emergency close 실행.
7. 결과: 정상 익절 직후 봇이 HALT 상태로 멈춤.

## 근본 원인

TP는 `quantity` 기반 주문이라 포지션이 없어도 Binance가 수락(성공처럼 보임)하는 반면,
SL은 `closePosition=True` GTE TIF라 포지션 부재 시 즉시 −4509를 반환하는 **비대칭 구조**가 혼동을 유발.

기존 `_place_sl_order`는 −4509를 처리하지 않아 알 수 없는 에러로 분류 → 무방비 판단 → HALT.

## 수정 내용

`AlgoNoOpenPosition`(−4509) 예외 케이스를 `_place_sl_order` 에 추가:
- SL 재배치 중 −4509 수신 시 → 포지션 부재 확인 후 HALT 없이 반환.
- 포지션이 실제로 존재할 때만 기존 무방비 HALT 로직 유지.
- 이미 청산된 포지션은 position-gone reconciler가 닫힘 처리를 담당.

## 교훈 및 후속 과제

0.4% 초타이트 전략은 TP·SL·추매 재배치 간 **레이스 컨디션**이 빈번히 발생한다.
엔진이 "포지션이 이미 청산된" 상황에 견고(graceful)하게 반응해야 한다.

- **모니터링**: HALT 발생 빈도, 추매-청산 레이스 빈도 추적.
- **검토 후보**: 추매 직후 SL/TP 재배치 전 포지션 존재 여부 선확인 강화.
